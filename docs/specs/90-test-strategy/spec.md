# Test strategy

[Constitution](../constitution.md) · [Live run protocol](../live-run.md)

Understood as: make PR tests faster **without losing evidence that commands work**, particularly Chromium paths; keep all verification synthetic except the separately authorized live protocol. Principle 1 precedes measured optimization (constitution.md:7-13). Current baseline, measured 2026-09-28 with Chromium hidden via `PLAYWRIGHT_BROWSERS_PATH`: 699 passed/44 skipped in 89.95 s on Ubuntu (job ~1m40s), Windows 3.11 job ~2m05s; ~99 s local CI-equivalent test time; local installed-Chromium suite ~5 min/740 passed. A Chromium-only headless fetch regression reached #48 and was fixed in #49. The browser executable checks currently skip (`tests/test_sync_all.py:354-363`, `tests/test_browser.py:750-763`, `tests/test_browser_options.py:88-95,132-149`, `tests/test_profile_documents.py:270-288`). These are baseline observations, **not** a promise about hosted runner timing.

## Proof layers and promotion

| Layer | Owns | Gate |
| --- | --- | --- |
| Pure/unit | Catalog identity, merge, persistence, error/status, timeout decisions with virtual time; no network or browser | Every PR, every pytest matrix job |
| Integration with fakes | Correlated response/DOM transitions, changed-page/identity rejection, stale-row retention, partial-domain continuation and lock semantics using synthetic IDs and `.invalid` hosts (`tests/test_cnu_notices.py:16-28`, `tests/test_sync_all.py:25-27`; `src/campusctl/providers/cnu/sync_all.py:431-474`) | Every PR, every pytest matrix job |
| Real Chromium + local synthetic HTTP server | Actual navigation, popup/session, readiness, combined sync, assignment/notice fetch, rendering, replay and packaging; no live account (`tests/test_sync_all.py:1-2,341-401`, `tests/test_browser_options.py:132-153`, `tests/test_replay.py:269-277`) | Every PR, one Ubuntu x86_64 job with installed Chromium |
| Live LMS | One owner-authorized full path, state before/after fetch, request/page/step timings and sanitized evidence; not CI, not a fixture substitute (`live-run.md:3-39`) | Only for LMS-facing behavior changes, under the existing protocol |

A live finding becomes a fixture **only after** owner-held raw evidence is reduced to observable inputs/transitions and expected output/error/state; replace all origins with `.invalid` or loopback, IDs and labels with synthetic values, omit traffic/bodies/credentials, and add the smallest unit/fake or local-Chromium regression that would have failed before the fix. Cite only `owner-held sanitized evidence (YYYY-MM-DD)` plus safe counts/timings; never commit the raw record or owner notes (`live-run.md:29-39`, `constitution.md:18-20`). Preserve actual request ordering/late transitions, not just a successful final row. No wiring/echo/source-text tests.

## Virtual-clock seam, not shorter production waits

Create `src/campusctl/wait_clock.py`: `Clock` protocol with `now() -> float` (running loop's monotonic `loop.time()`), `async sleep(seconds)`, and `async wait_for(awaitable, seconds)` (real defaults delegate exactly to `asyncio.sleep`/`asyncio.wait_for`); `current_clock()` reads a task-local `ContextVar` defaulting to the immutable real clock, and `use_clock(fake)` sets/resets it in `finally`. The same protocol provides `monotonic()`/`sleep_sync(seconds)` for synchronous bounded retries (real defaults `time.monotonic`/`time.sleep`). Replace each **coherent wait's** deadline clock, sleep and timeout together, not just its sleep. Have `browser.bounded` use the same clock's `wait_for` without changing its `browser-timeout` conversion (`src/campusctl/browser.py:440-449`). The async fake maintains a monotonic virtual timestamp and queued sleepers/deadlines; tests explicitly call `advance(delta)` then yield the event loop until ready tasks settle; its sync sleep advances that same timestamp. Expired `wait_for` cancels the underlying task, never turning an unfinished request into a success. Never monkeypatch global `asyncio`, time, or Playwright. Real-browser and CLI runs always use the default clock. Keep real timeout values, ordering, safety cancellation and error codes; no new CLI/config flags or changed page requests.

Inventory: readiness's route/identity/surface deadline and 50 ms polls (`readiness.py:75-96,113-169`); to-do's 0.5 s quiet window, 1.5 s no-control proof, 50 ms polls, page deadline and outer 120 s cap (`notices.py:23-24,420-503`) plus board polling (`notices.py:728-742`); archive response/completion and state/modal polls (`materials.py:254-282,472-489,513-578`); course identity, assignment and detail polls (`course_context.py:27-38`, `assignments.py:296-301`, `notice_detail.py:398-402`); login's shared response deadline, fetch/body/click/result waits and cleanup (`login.py:92-93,165-190,212-259,281-300`). The outer notice `asyncio.timeout(120)` must use the same clock-backed timeout around its existing extraction coroutine, with unchanged exception/cancellation semantics. `sync_all.py` has no direct sleep: its `_todo`, roster return, selection, domain collectors and login inherit the task-local clock (`sync_all.py:278-284,346-418,431-474`). Audit other genuine retry waits, including player loops (`player.py:253-262,395-430,464-473,501-529`) and the synchronous catalog lock retry (`catalog_view.py:168-181`); virtualize the latter through `monotonic`/`sleep_sync`, but preserve actual filesystem lock acquisition. External browser, subprocess, OS-lock and credential-helper timeouts must still expire under the real clock in real runs; virtual-clock tests must supply fake external events rather than wait for real I/O. Never fake elapsed performance/profile measurements.

Convert late-Next tests to schedule an event at virtual +0.6 s instead of reading wall time (`tests/test_cnu_notices.py:762-831`); cover quiet/no-control boundaries, late Next before the 1.5 s boundary, actual timeout, listener/route cleanup, and the same error code. Timed fake waits should settle without wall sleeping; retained real-browser tests prove the default branch. Three late-Next parameter cases currently cost ~2.6 s each; eliminating those alone can save **up to ~7–8 s** of test runtime, while notice-board agreement waits, archive waits and profile fixture remain additional candidates (`tests/test_profile_sync.py:52-69`). Total ~10–20 s off the ~99 s CI-equivalent local suite is a **hypothesis**, not a measured gain; record before/after `--durations=20` on the same host and reject speedups that lose behavioral assertions. #47's wall-clock fix is the determinism precedent.

## Parallelism and OS × Python coverage

`pytest-xdist` is not in `pyproject.toml:18-25`; do **not** enable `-n auto` first. Worker processes isolate monkeypatched environment/module globals (`tests/test_foundation.py:193-201`, `tests/test_command_discovery.py:36-45,71-113`), but not shared filesystem, subprocesses or network: keep every `CAMPUSCTL_CONFIG_DIR`/`CAMPUSCTL_DATA_DIR`, browser profile, output, snapshot and lock beneath each test's `tmp_path` (`src/campusctl/browser.py:349-352`, `tests/test_browser.py:180-190`, `tests/test_assignments_integration.py:70-88`); bind HTTP on port 0 and close servers/threads (`tests/test_sync_all.py:341-351`, `tests/test_browser.py:790-824`). Replace the bind-to-zero/close/rebind CDP port race (`tests/test_browser.py:827-850`) with a coordinated reserved port/startup check, or keep that file serial. Audit any process-wide cwd changes and fixed `/tmp` paths; restore or relocate them per worker. Tests importing fixtures across files (`tests/test_assignments_provider.py:122-146`, `tests/test_profile_documents.py:199-200`) must not share mutable server state or cached output. Keep actual lock-contention assertions cross-process (`tests/test_foundation.py:970-974`), not fake locks. Gate xdist after a repeatable Linux fake-only `-n 2` run **and** serial equivalence; do not parallelize Chromium on a memory-constrained host. Measure before enabling in CI; xdist is optional if setup/scheduling erases the clock gain.

The owner-approved matrix **replaces**, rather than expands, the current five pytest entries (`.github/workflows/ci.yml:76-104`). It keeps five pytest checks, plus a separate browser check, Windows smoke, lint and leak scan: **nine required checks** on every PR, main push and release tag. The existing `requires-python >=3.11` (`pyproject.toml:12`) and Windows/macOS/Linux support (`README.md:5,23-28`) ground the platform/version selection; the owner's project venv is Linux arm64 CPython 3.12 and the host's system Python is 3.13. GitHub lists [`ubuntu-24.04-arm` as a standard public runner](https://docs.github.com/en/actions/reference/runners/github-hosted-runners#standard-github-hosted-runners-for-public-repositories). Python 3.14 is not added without a supported user runtime or dependency need. Windows 3.11 and 3.13 jobs are dropped; **accepted residual risk:** Windows-version-specific failures outside 3.12 (owner decision, 2026-09-28).

| Required check name | Distinct bug class it catches |

| `pytest (ubuntu-latest, Python 3.11)` | Minimum-supported interpreter incompatibilities: syntax, standard-library and dependency behavior at 3.11 |
| `pytest (ubuntu-latest, Python 3.13)` | Newest in-use interpreter incompatibilities: owner host's system Python 3.13 |

| `pytest (windows-latest, Python 3.12)` | Windows paths, processes, keyring and Proactor event-loop behavior |

| `pytest browser (ubuntu-latest, Python 3.12)` | Actual Chromium navigation, readiness, session, sync and fetch regressions against a synthetic server |
| `Windows installation and runtime smoke` | Installed command shims, headed Chromium launch and disposable Credential Manager round-trip (`ci.yml:106-241`) |
| `Lint and format` | Ruff static/style failures (`ci.yml:19-31`) |
| `Leak scan` | Committed secret exposure and public-tree hygiene (`ci.yml:33-74`) |

## Browser and CI gate

Run the separate required `pytest browser (ubuntu-latest, Python 3.12)` job **in parallel** with the five browser-free pytest matrix entries. Keep `uv run pytest -q -o faulthandler_timeout=30` for all five unit jobs (`ci.yml:95-104`); never set `CAMPUSCTL_REQUIRE_CHROMIUM` there, and hide any runner browser via `PLAYWRIGHT_BROWSERS_PATH` pointing to an empty job-private directory if needed. In the new x86_64 browser job, `uv sync --locked --python 3.12`, cache **browser binaries** at `~/.cache/ms-playwright` using `actions/cache@v4` with OS + arch + `hashFiles('uv.lock')` key, then run `uv run playwright install --with-deps chromium`; cached binaries do **not** replace `install-deps` system packages. Set `CAMPUSCTL_REQUIRE_CHROMIUM=1` **only on this job** and run the browser-inclusive full `uv run pytest -q --cov=campusctl --cov-report=json:coverage.json -o faulthandler_timeout=30` once, with coverage reporting from the same run. Register `chromium` pytest marker on every real-Chromium test and a session-level guard: when the flag is set, fail if Playwright or its Chromium executable is absent, if zero marked tests were collected, or if **any marked test** skips (including low memory and unavailable CDP); preserve legitimate platform skips on unmarked tests. Convert every Chromium availability skip/helper, not just `_chromium()` (`tests/test_sync_all.py:354-363`, `tests/test_browser.py:750-763,827-850`, `tests/test_browser_options.py:87-95,132-149`, `tests/test_profile_documents.py:275-288`, `tests/test_replay.py:269-273`, `tests/test_roster_diagnostics.py:27-30`, `tests/test_sso_settle.py:21-25`). Make the guard's own missing-browser and no-selected-tests cases fail visibly; leave optional skips on other jobs. Assert the #48/#49 headless fetch, combined sync, readiness, cookie/session and fetch cases actually execute in the browser job (`tests/test_browser_options.py:132-149`, `tests/test_sync_all.py:354-401`, `tests/test_browser.py:759-825`). Do not use an `-m` selection that omits nonbrowser regressions.

When the CI PR merges, replace branch-protection/orchestrator contexts for `pytest (windows-latest, Python 3.11)`, `pytest (windows-latest, Python 3.13)` and `pytest (ubuntu-latest, Python 3.12)` with `pytest (ubuntu-latest, Python 3.11)`, `pytest (ubuntu-latest, Python 3.13)`, `pytest (ubuntu-24.04-arm, Python 3.12)` and `pytest browser (ubuntu-latest, Python 3.12)`; retain the other five named checks from the table. This is nine required checks, with no permanently pending contexts (owner decision, 2026-09-28). A nightly or manual non-required job may repeat full browser runs and collect trends; it is never the only proof of browser changes. Current workflow triggers are PR, main, tags and manual, not nightly (`ci.yml:3-9`). Target PR feedback **≤6 min warm-cache, ≤10 min cold-cache** pending hosted p95 measurement: local browser-inclusive suite ~5 min plus setup; existing Windows 3.11 job ~2m05s. Track p50/p95 job duration and skipped Chromium counts; do not reduce browser cases to hit the target.

## Coverage: evidence, not a score

The CI-equivalent baseline is 82% / 8,577 statements (2026-09-28), measured **without Chromium**; do not compare it directly with a Chromium-inclusive report. Pin pytest-cov in the dev group/lockfile, and on the browser job collect `uv run pytest -q --cov=campusctl --cov-report=json:coverage.json -o faulthandler_timeout=30` rather than rerunning the suite solely for coverage. Store the main-branch report from the same Ubuntu x86_64 3.12 + Chromium configuration. For each module, show the PR versus main `files[path].summary.covered_lines / files[path].summary.num_statements` delta in the browser job's summary (use unrounded ratios and note added/removed modules); report missing main baseline explicitly. For PRs, compare changed source lines against `executed_lines` and `missing_lines` and list uncovered changed statements in the browser job summary. The reviewer reads this report and requests tests for risky uncovered lines. **Coverage is permanently report-only, never a failing gate** (owner decision, 2026-09-28), including when the baseline or diff is unavailable. Coverage is a risk signal, not a reason for tautological assertions. Never run another full browser suite solely to measure coverage on the RAM-constrained owner host.

Prioritize paths where wrong outcomes matter: `sync_all.py` (17%) course selection, per-domain failure staging, stale retention and publication after close (`sync_all.py:77-97,431-474`); `sync.py` (54%) empty rows versus wrong-course/timeout (`sync.py:66-98`); `credentials.py` (56%) credential helper failure and timeout (`credentials.py:432-442`); `lock.py` (60%) contention and cleanup (`browser.py:349-376`, `tests/test_foundation.py:970-974`); `roster_diagnostics.py` (63%) bounded diagnostic failure and privacy (`roster_diagnostics.py:69-78,282-285`); `course_context.py` (70%) topbar identity wait (`course_context.py:27-38`); `assignments.py` (76%) delayed/mismatched rows (`assignments.py:296-301`); `browser.py` (79%) lock/timeout/cleanup (`browser.py:440-449`). These percentages are the **no-Chromium** baseline, not a claim that all branches are untested with Chromium. A regression test must assert observable rows, errors, persisted state and no unintended requests; no wiring, mock echo or source-text tests.
