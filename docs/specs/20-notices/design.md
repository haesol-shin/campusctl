# Notice board implementation design

## Owner decision (2026-09-26)

Board lists establish complete per-course coverage; the global `/std/todo` list supplies only read-state enrichment. Per course the guarded navigation is `/std/myLecture` → `POST /api/v1/course/addSessionCourseInfo` → `/std/lecture` → `/std/notice`, followed by `POST /api/v1/board/notice/list/top` and `/api/v1/board/notice/list`. A second page fails the course, retaining its old rows. Suppressed optional requests stay aborted. Never navigate notice details or call `/api/v1/board/notice/info`.

## Request and course binding

The operation policy lives only in `commands/notices.py`: exact LMS origins, GET documents `/std/myLecture`, `/std/lecture`, `/std/notice`, `/std/todo`; localization XHR with optional numeric cachebuster; exact POST shared-page and board routes observed in owner-held sanitized board evidence dated 2026-09-26; static same-origin scripts/styles/fonts/images under the existing guarded asset rules. The exact Panopto SAML script, observed `/upload/dunetadmin/college/{hash}.png`, `/assets/images/favicon-{hash}.ico`, and external telemetry `http://0.0.0.0:3000/v1/events` are suppress entries with operation `notices.sync`; passive outside-origin GET assets use built-in `third-party-asset`. Owner decision 3 permits exact LMS POST `/api/v1/week/getStdActivityStatus` XHR from `/std/lecture` as a read-only route with `logging_token_reviewed:true`, because aborting it displays a blocking server-communication modal. Other unsuppressed logging-token paths remain blocked. Unapproved data requests, media, Range and redirects remain fatal. Full observations and suppression bisection are preserved as owner-held sanitized LMS board evidence dated 2026-09-26.

The provider authenticates before interception and installs a single guarded interceptor. It loads roster metadata, reads the settled to-do grid, then enters each selected course from its roster row. Before each navigation, wait for network idle; record request sequence and main-frame commit. Require exactly one session-course selection POST before the notice document, course ID in its body and rendered course ID that matches the selection; if no ID is rendered, the displayed name must match exactly one roster course. An ID mismatch cannot be overridden by a matching name. Require exactly one top and one ordinary list request after `/std/notice` commits, ordered by request sequence, both main-frame POSTs with exact `/std/notice` Referer. Both HTTP statuses and `header.code` must be 200. Observed top response shape is `{header:{code,msg},body:{list}}`; ordinary shape is `{header:{code,msg},body:{total,list}}`, with numeric total. Source rows include `boarditem_no`, `boarditem_title`, `row_idx`, `insert_dt` (day), `insert_dt_addtime` (timestamp), `writeruser_name`, `boarditem_viewcnt`, numeric `file_yn`, `course_id`, and `delete_yn`. Exclude deleted rows; reject course-ID mismatch, stale response or duplicate response. Never copy `writeruser_phone`, `writeruserno`, or `ref_user_no`, and never infer unread from `read_cnt` or `new_yn`.

The first board table's `tbody#table-body > tr` supplies only rendered row count and pagination. `data-page-size` is 10. Enabled Next, numeric page 2+, ordinary total >10 or ordinary response list length below total fails with `notice-board-paginated`. Deduplicate top/ordinary response rows by `boarditem_no` and require their nondeleted count to match the DOM count. A verified-empty course requires ordinary total 0, ordinary list empty, top list empty, and DOM count 0. Any mismatch retains the old rows as stale. These checks use the observed owner-controlled response envelope, not an invented zero default.

The historical legacy notifier parser (owner-held sanitized parser evidence, 2026-09-25) uses `<trimmed course label>_<trimmed displayed date>_<trimmed ordinal>`. The board DOM day `insert_dt` differs from its response `insert_dt_addtime` timestamp (`YYYY-MM-DD HH:MM`); use the latter when valid and the displayed day only as a fallback. Join a to-do row by native ID when available, otherwise only when course, title and date-day identify a single board and to-do row. A match preserves the exact to-do timestamp/ordinal, including its historical entity ID; ambiguous candidates fail the course with `notice-identity-ambiguous` and retain old rows. Board-only rows use their own source timestamp/ordinal and never fabricate a historical to-do key. `writeruser_name` is author, not author role; numeric `file_yn` 0/1 is attachment false/true, while unavailable indicators remain null. No global-only row becomes a notice. Atomic catalog merge retains old rows on per-course error; cached listing remains lock-free and headless sync unapproved.
