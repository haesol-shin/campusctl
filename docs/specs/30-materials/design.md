## CLI and output (FR-002–FR-010, FR-017, FR-019)

### CLI commands and flags

```text
campusctl sync --only materials [--course COURSE_ID] [--headless] [--json]
campusctl materials list [--course COURSE_ID] [--json]
campusctl materials download ENTITY_ID [--out DIRECTORY] [--headless] [--json]
```

`--headless` is opt-in for network commands only; default stays visible, and the flag must be rejected unless its CNU compatibility is independently established. PR1 reserves the parser flag and extends `open_session(..., headless=False)` but does not authorize its use with lectures; external CDP mode cannot control the browser's headless setting. `list` uses disk only; `--json` anywhere explicitly selects agent JSON; without it, terminal defaults human (honor existing `CAMPUSCTL_OUTPUT` override). Accept one full, opaque `entity_id` returned by list; do not parse caller-side or accept multiple download IDs. Validate presence, identity, and `downloadable` **before** acquiring a browser or requesting file bytes. [Plan owner-held sanitized planning notes (2026-09-25, lines 23-38,176-178); `src/campusctl/cli.py:300-308,437-479`; `src/campusctl/browser.py:286-296,343-355`; foundation-coordinated headless hook]

Local persistent Chromium `materials download --headless` is compatible with the reviewed download operation; metadata sync remains visible-only. The official `fileDownload` response is checked for a successful header, and LCMS `body.is_cms:true` yields one exact URL from `/upload` plus the encoded relative `body.path` after verifying `body.name` matches its basename. The context interceptor fetches and binds this metadata before fulfilling the POST so the browser's own document GET cannot precede binding; only the exact already-bound redundant browser document GET is aborted. The separately guarded context-request GET supplies the validated bytes. Other storage requests remain denied; only the owner-reviewed Panopto SSO popup document POST is suppressed for non-playback operations (see the foundation policy delta).

A complete course contributes one row per official file target. Empty posts contribute none; several targets in a post contribute several. Raw `display_name` is exactly LMS-visible text (including actual trailing whitespace); `filename` removes only a *trailing* `바로보기` label and optional adjacent whitespace, **before** MIME/extension classification or safe naming. Without `Content-Disposition`, use the selected official control's text or `getAttachFileList` filename, never the storage URL's often opaque basename. An interior occurrence is not removed. Use PR1 `identity.material_entity_id(course_id, file_id)` to produce `cnu_lms_material:<course_id>:<file_id>`; dedup key `(course_id, file_id)`. A repeated ID for two targets in one course rejects that whole course. Only a verified official, approved-origin, owner-supported non-video type is `downloadable:true`; otherwise preserve a metadata-only row. `media_type` is an independently verified pretransfer MIME or `null`, `size_bytes` the known nonnegative integer or `null`; extension alone cannot establish a MIME. [FR-003–FR-005, FR-020; `src/campusctl/identity.py:23-25`; decision owner-held sanitized policy decision (2026-09-25, lines 23-32); observed no Content-Disposition and opaque storage filename (owner-held sanitized observation report, 2026-09-25, lines 195-238)]

The archive discovery order is: click a specific archive file icon; inspect the shared `#file_download` modal; if unavailable/empty, inspect inline `[data-act="downloadFile"][data-id]` targets. The post-detail `/std/archiveView` fallback was removed because it has no reviewed route pin: if neither modal nor inline controls resolve a post, fail its whole course. Restore the archive list after inspecting each post. Collect board item ID and title with each target, without clicking download controls during sync. An absent archive menu or absent file icons is a verified empty course only when bounded UI observation establishes it; malformed entry/timeout/restore failure marks the whole course failed, not an empty success.

This field is required on every successful download result. The returned `path` is absolute, while `filename` remains the label-free original and may differ from its safe/collision-adjusted basename. No persisted download URL, signed query, cookie, credentials, or Playwright exception text. ### Errors and exits

Use safe `{code,message,remediation}` fields, never raw URLs/errors. `catalog-missing`, `catalog-invalid`, `catalog-schema-unsupported`, `course-not-found` (unknown filtered sync ID), `entity-unknown`, `unsupported-media-type` (including `downloadable:false` or signature mismatch), `file-too-large`, `output-path-conflict`, `headless-unavailable` (uncleared opt-in), and invalid usage are `user-action`/2; missing catalog remediation is `campusctl sync --only materials`. `session-busy` is `busy`/75. Course failures (incomplete archive enumeration) are `course-sync-failed`, `partial`/1; missing/duplicate file identity is `item-identity-missing`, `partial`/1; both retain the prior whole course. Full discovery failure is `course-discovery-failed`, `error`/1. `policy-blocked` covers attempted unapproved request/redirect/logging (`error`/1); `download-failed` covers non-200, empty, or interrupted response (`error`/1); `catalog-write-failed` and file I/O are operational `error`/1. No failure publishes a partial file. The existing envelope has `ok`/0, `partial` or `error`/1, `user-action`/2, `busy`/75. ### Attachment classification and response guard (FR-005, FR-010–FR-011, FR-020)

| --- | --- | --- |
| pdf | `%PDF-` | observed, `application/x-pdf` |

| zip | `PK\x03\x04` | observed, `application/zip` |
