# Materials collection and download design

[Requirements](spec.md) · [Constitution](../constitution.md)

After the shared verified course selection, click the archive menu and capture its course-bound list response. Open each post's file icon to enumerate the shared modal; inspect inline `[data-act="downloadFile"][data-id]` controls if the modal is unavailable. An unresolved post or missing/duplicate native file ID fails that course. Catalog rows bind `course_id`, archive post/board ID and file ID. Empty posts add zero rows; sync never transfers file bodies. A failed course retains old catalog rows with a stale warning.

Download resolves exactly one full row ID (human number/picker first resolves to that ID), checks downloadability, takes the shared session lock and checks a same-ID/same-output receipt. Otherwise it navigates through the official course/archive controls and verifies the parent post and selected file ID. Obtain the actual file URL from its official control or successful fileDownload response, not an invented URL. Reject a different file, unexpected redirect or unsuitable response. Stream at most 200000000 bytes; inspect file extension plus signature/text and strict observed PDF/PPTX/ZIP MIME pairs. Never save video/audio or extract ZIP. Unknown MIME alone cannot admit a file.

Sanitize the official filename, confine it below the chosen output directory, enforce the 200-byte component limit and Windows absolute-path limit, and use an exclusive temporary file plus no-clobber atomic publication. Reuse identical bytes or choose a deterministic full-content-digest suffix for conflicting basenames; do not follow symlinks. A private atomic receipt records ID, absolute destination, size and SHA-256. Page requests are not guarded; these selected-file checks apply only to the transfer.
