## Problem and evidence

- README opens with implementation detail, repeats the same install command for three OSes, then gives 11 quick-start commands and dense profile, selector and browser rules (`README.md:12-12,26-85`). The last FAQ answer includes package/JSON schema detail (`README.md:172-174`); a contributor-only scan-exceptions section occupies `README.md:150-152`. Korean README is separate but has the same sprawl and says detailed docs are English-only (`README.ko.md:8-13,27-86`). Keep the core definition first: **campusctl shows CNU students their lectures, assignments, notices and materials in a local CLI or an AI agent; it syncs through the normal LMS browser.** CNU is the only supported provider (`docs/contracts/cli.md:1-5`).
- Observed `uv run --locked campusctl --help` on v0.5.1: “Campus LMS control CLI”; parser-order commands start with `config`; `setup` says “install or check the local Chromium browser”; global browser flags have no descriptions (`src/campusctl/cli.py:62-145`). Domain help is defined in `src/campusctl/commands/assignments.py:90-101`, `src/campusctl/commands/notices.py:110-124` and `src/campusctl/commands/materials.py:27-40`. `--only` accepts comma-separated domains (`src/campusctl/sync.py:16-25`), so argparse `choices` cannot directly represent the value.
- Observed `CAMPUSCTL_OUTPUT=human campusctl status` with an empty isolated data directory: it prints three zero-count sections and then `catalog-missing`/exit 2. `status` raises with no readable catalog (`src/campusctl/status.py:151-221`); the CLI catches that error (`src/campusctl/cli.py:694-701,903-912`), while `_status` renders the empty `result` as three zeros before the error (`src/campusctl/presentation.py:520-548,714-761`). Other missing-catalog messages interpolate an absolute path (`src/campusctl/catalog.py:28-39`; `src/campusctl/domain_catalog.py:76-91`).
- Non-TTY stdout auto-selects JSON after explicit `--json` and `CAMPUSCTL_OUTPUT` precedence (`src/campusctl/cli.py:378-386,828-842`; `docs/contracts/cli.md:31`). Human/JSON output and exit statuses use the same versioned envelope (`src/campusctl/cli.py:320-344`; `docs/contracts/cli.md:126-156`). Existing skill consumers use JSON (`docs/agent-skill.md:25`; `skills/campusctl/`); external scripts may do so too.
