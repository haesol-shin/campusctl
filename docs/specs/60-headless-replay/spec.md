# v0.4.0 — headless execution and explicit replay

[Constitution](../constitution.md) · [Design](design.md) · [Tasks](tasks.md). This specifies ordinary official-player replay and browser-mode selection, not attendance simulation. No seek, position/rate writes, visibility spoofing, media capture or alternate player. The owner explicitly permits completed/recorded replay; nothing changes the normal completion refusal without `--replay`.

## Contracts and evidence boundary

- Global mode syntax and precedence belong to [50 UX](../50-v040-ux/spec.md): `campusctl --headless sync`, `campusctl --headed lectures play <entity-id> --replay`. Default is headed on every OS. Headless changes browser presentation, not allowed routes or completion semantics.
- Allow headless sync for all four domains only after the per-operation release gates below. Owner reports assignment/notice/material sync verified across 7/7 courses with matching counts. That is supplied evidence, not a claim that this spec ran it, and not proof of complete record equivalence or lecture/play/download compatibility. Checked-in domain/provider guards still reject it (`commands/materials.py:206-218`, `providers/cnu/assignments.py:315-326`, `providers/cnu/notices.py:728-738`, `cli.py:454-461`).
- **Verified playback, failed download, remaining scoped gates:** owner-authorized Panopto headless playback of one completed lecture passed a roughly 180-second 1.0x observation on 2026-09-26: currentTime increased 178.58 seconds, the page remained visible, and its F/complete, 26/26-minute row was unchanged; peak RSS was 1,135.72 MiB. The report records an initial paused/not-ready sample before advancing playback, not a later pause. This proves the observed playback interval, not end-to-end replay completion or additional attendance credit. YouTube and first-time incomplete-lecture attendance remain unverified. At that observation, material download headless **FAILED** with policy-blocked and remained disabled pending diagnosis plus a new authorized live pass; no policy relaxation without separate owner approval. Evidence: owner-held sanitized headless download/playback report (2026-09-26, observations 3–27). Unsupported operation/player/outcome combinations return headless-unavailable/user-action/2 before browser or publication; do not treat all playback as unverified or enable all playback from this one result. Full sync preflights every domain. CDP retains its headless refusal (`browser.py:293-299`); fetch retains 40's gates.
- `lectures play ENTITY_ID... --replay [--speed 1.0|1.25|1.5] [--json]` accepts a finite explicit full-ID set, deduplicated first-seen. No number, title, wildcard, range, implicit all, or empty selection. Validate every selected record before a browser is opened. `--replay` only overrides complete/recorded refusal and corresponding live pre-play skip; it never overrides unknown ID, closed availability, unsupported media, speed, authentication or policy errors (`player.py:142-202,901-948`).
- Human replay requires dual-TTY confirmation, default no, once for the full validated set with titles/full IDs/count. No/no-input/EOF causes `replay-cancelled`/user-action/2 and no browser; human mode without terminals causes `replay-confirmation-required`/user-action/2. JSON never prompts: `--replay` is the caller's explicit attestation of selected user intent. The agent skill must first obtain explicit user intent to replay those completed/recorded IDs; 'show remaining', ordinary 'play all', or a stale previous choice is not that intent. Do not add a blanket `--yes` escape.
- Replay uses the official play control from the player's naturally presented position. Never reset to zero by writing/seeking. Existing video speed menu remains authoritative; YouTube stays native autoplay at 1.0, with read-only rate checking (`docs/contracts/cli.md:42-44`; `player.py:949-973`). No playback concurrency or fabricated completion.

## Outcomes and acceptance

Retain current `items` outcome vocabulary and error/queue semantics (`docs/contracts/cli.md:87-95`; `player.py:975-1087`). Add `replay_requested:boolean` and `player_opened:boolean` per item. An already-complete row with replay must actually open the official player before it can report a successful played result; stale state F alone cannot satisfy replay. After native playback finishes, verify the official row exactly as normal; report completed/recorded/unverified, without claiming new attendance credit. A failed or unverified item stops the remaining queue; later items are not-started. Default non-replay behavior remains byte-compatible except additive fields.

Fixtures prove catalog complete/recorded and live complete/recorded all open when replay is explicitly authorized, while normal mode refuses/skips as before. Prove media/closed/speed failures still prevent opening, confirmation happens before lock, and rate/position/visibility mutation never occurs. Separately authorized live gates must demonstrate actual official-player behavior; synthetic traces alone do not establish headless compatibility.
