# Configurable material download layout

[Constitution](../constitution.md) · [Live run protocol](../live-run.md) · [Materials contract](../../contracts/materials.md)

## Scope and evidence

- The current download chooses `--out` or `<Downloads>/campusctl/<safe course label>`, prepares the directory and checks a same-ID/same-directory receipt **under the session lock**, before LMS authentication; after the verified official transfer it publishes and writes a receipt (`src/campusctl/commands/materials.py:185-223,280-299`). Keep selected-file identity, type/signature, 200,000,000-byte limit and no-range behavior unchanged (`docs/specs/30-materials/spec.md:7-9`).
- The materials row contains `course.id` and `course.label`, **not a semester** (`src/campusctl/providers/cnu/materials.py:178-190`). The catalog course roster has `course_id`, `label`, `class_no` (`src/campusctl/providers/cnu/courses.py:10-23,31-43`; `src/campusctl/domain_catalog.py:347-373`). Do not infer a semester from an ID, class number, transfer URL or sync timestamp.
- `safe_component` NFC-normalizes, strips path prefixes, replaces control/Windows-forbidden characters, trims trailing spaces/dots, substitutes `resource` for empty/reserved names, and truncates to 200 UTF-8 bytes while preserving suffix/extension (`src/campusctl/material_files.py:22-24,55-91`). Because it strips prefixes, validate template values **before** calling it. The material row already removes the trailing `바로보기` and adjacent whitespace from the official display name (`src/campusctl/providers/cnu/materials.py:52,146-155`). Windows publication also enforces a 250-UTF-16-unit absolute-path budget (`src/campusctl/material_files.py:239-249,320-333`).

## Config and path contract

Add `[materials]` in `config.toml` (`src/campusctl/config.py:32-73`; `docs/configuration.md:35-56`):

```toml
[materials]
semester = "2026-2" # optional user-supplied literal, not LMS/catalog metadata
download_dir = "~/School/{semester}/{course}/01_materials"
adopt_existing = true # optional; default false
```

- `download_dir`: optional nonempty TOML string. Without it, preserve the existing platform Downloads default (redirected Windows known folder, Linux XDG, macOS `~/Downloads`; `src/campusctl/material_files.py:107-158`). `--out DIRECTORY` always takes precedence **for this call** and disables recursive adoption for that call; it remains an ordinary directory argument, never parsed as a template (`src/campusctl/commands/materials.py:37-40,216-219`). A template's final expanded directory is the output directory, not its parent.
- Exactly three placeholders: `{course}` = row `course.label`; `{course_id}` = row `course.id` (`src/campusctl/providers/cnu/materials.py:178-181`); `{semester}` = explicit `materials.semester`. No other placeholders, format expressions, conversions or escaped braces. `semester` is an optional nonempty string, REQUIRED only when `{semester}` appears; it is **not** taken from the current catalog. This makes the example usable without a new LMS discovery contract. Reject unresolved placeholders or absent semester with `config-invalid` naming `materials.download_dir` or `materials.semester` (the existing config error shape is `src/campusctl/config.py:17-23`).
- Each placeholder expands to **one** `safe_component` output. Reject empty/whitespace-only raw values, a leading slash/backslash, drive/UNC prefix, any `.`/`..` path segment, and control characters before sanitizing. For catalog `course.label`, replace any remaining embedded `/` or `\` with `_` (do not let `safe_component` drop the preceding text); `course.id` and user-supplied `materials.semester` must contain no separators at all. Apply `safe_component` to the whole validated value (including the configured semester), NFC and 200-byte bound. Do not interpolate raw catalog text into the filesystem. A literal template path component must likewise be nonempty, neither `.` nor `..`, contain no control or Windows-forbidden filename characters (except the path's drive/UNC anchor), and fit the same NFC/200-byte bound; reject unsafe literals rather than silently rename them. Reject mixed placeholder/literal components: each placeholder must occupy an entire component. Distinct original course values that sanitize to the same component are not guaranteed separate folders; `{course_id}` may be included as its own component to disambiguate.
- Expand leading `~/` (or Windows `~\\`) to the current user's home on all three OSes; reject `~other`. Expand **defined, nonempty** `$NAME` / `${NAME}` on POSIX and Windows, and `%NAME%` on Windows, using the process environment; reject unset/empty references, not silent literal preservation. Expand environment variables before checking the anchor and literal components; an env value supplying an absolute anchor is permitted only at the start. No shell execution, recursive expansion or relative paths: after expansion and interpolation require an absolute native path; POSIX `/`, Windows drive-absolute or UNC. Reject traversal and absolute/separator-bearing injected components; check all ancestors without following symlinks or Windows reparse points before creating the destination privately. Overlong paths return existing `output-path-too-long`, otherwise unsafe filesystem paths return `output-path-conflict` (both user-action/2; `src/campusctl/material_files.py:94-100,161-213,239-249`). Bad template syntax or values return `config-invalid`/2 **before** authentication or creation. No config content or user home path in error details beyond the named key.
- Reject Windows reserved device basenames (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, including extensions) and trailing space or dot in every **literal or environment-expanded path component**, on all platforms, before creation; these must not be silently renamed or allowed to alias another directory. Apply this check after variable expansion as well as to static template literals; the volume/UNC anchor is not a component. Placeholder values still use the `safe_component` normalization above (`src/campusctl/material_files.py:22-24,55-91`).
- `adopt_existing` accepts only TOML Boolean, defaults false. It requires `download_dir` with **exactly one** whole-component `{course}` or `{course_id}`; both together or repeated course placeholders are invalid when adoption is enabled. The **course root** is the resolved prefix ending at that component; the destination may be the root or a child (for the example, search `~/School/2026-2/<course>/`, publish to its `01_materials/`). The root must itself pass the same no-symlink/reparse directory checks. No adoption with only default Downloads or explicit `--out`. This is opt-in even for configured templates: a new folder layout must not silently scan user files.
- With adoption enabled, the destination must lie within the four-level search bound below its course root; reject a deeper configured suffix as `config-invalid` rather than claim a search that cannot cover the output folder. Static TOML/template errors are checked at config load; environment expansion and course-dependent values are checked when resolving a download (and resolvable environment references in `doctor`), before destination creation or authentication.
- `doctor` reads and validates settings without creating a destination or searching files (`src/campusctl/cli.py:178-193,242-277`; `docs/configuration.md:68-78`). In JSON `result.materials` add `{"download_dir":"<configured raw template or null>","adopt_existing":false,"semester":"<configured literal or null>"}`; with valid settings these describe configuration, **not** a resolved per-course path. For missing/invalid configuration use `null` values and the existing first `config-missing`/`config-invalid` error. Human doctor adds `Materials downloads: default` or `Materials downloads: configured (adoption on/off)` without echoing raw path or semester; invalid configuration keeps the normal actionable error. Extend `docs/configuration.md` and the doctor JSON shape in `docs/contracts/cli.md` (`src/campusctl/presentation.py:289-374`).

## Adoption, receipts and results

- Keep the existing verified transfer before adoption: revalidate the selected row, fetch the official attachment into the selected output directory, check downloaded size/digest, then search using that temp's bytes; **never** decide from name/hash alone or skip the download on a first-time adoption (`src/campusctl/commands/materials.py:228-299`). A valid receipt is the sole pre-authentication fast path.
- Search the course root, including the root and destination, in deterministic relative-path order to at most **4 child-directory levels**, **10,000 entries total** (files and directories; root excluded), and **1,000,000,000 aggregate bytes read from eligible existing files during byte comparisons**. Count bytes actually read, not merely declared file sizes; stop with `output-path-conflict`/2 and scan-specific remediation before exceeding any bound. No following directory symlinks, file symlinks, junctions/reparse points or special files. Eligible files are regular non-symlink files whose basename matches the **primary destination filename** after current Windows shortening, NFC normalization and Unicode casefold (`src/campusctl/material_files.py:320-333,418-436`). Enumerate and order candidates independently of filesystem iteration order; compare size first, then all bytes against the downloaded verified temp in that order. Pin/open directories and files without following links, and recheck inode/name identity before recording a path. Different bytes do not match. Unreadable directories/candidates or a path race also return the scan conflict rather than publishing a misleading new copy.
- Prefer an identical file at the exact primary destination path, then any other identical file **inside the output directory**, then an identical file elsewhere under the course root. Within either latter group, select the lexicographically smallest tuple `(NFC(relative_path).casefold(), NFC(relative_path), relative_path)` (relative paths use `/` separators). All same-directory matches, including case/NFC variants, report `reused`; only a match outside the output directory reports `adopted`. If no match, retain same-directory `publish_attachment` no-clobber/collision behavior, including digest-alternate reuse (`src/campusctl/material_files.py:356-491`).
- Receipts currently require exact entity ID **and absolute output directory**, and require `path.parent == output_dir` (`src/campusctl/material_files.py:529-561,590-654`). Move private `materials/receipts.json` to schema 2, reading schema 1 for compatibility and atomically writing schema 2 on next update; do not discard existing receipts. Each v2 item has the existing six fields plus `course_root: string|null`: `null` for `saved`/`reused`, absolute root for `adopted`. Record `path` as the **actual adopted file path** and `output_dir` as the resolved destination; keep one record per `(entity_id,output_dir)` and existing URL/credential exclusion. A v1 receipt remains eligible only when its recorded file is directly in the same output directory. An adopted v2 receipt may return `skipped-existing` only if its recorded entity and output directory still match, adoption is currently enabled for a configured template (not `--out`), the **current** course root equals its stored root, and its non-symlink regular target is still within that root at the bounded depth with the recorded size and SHA-256. Validate every ancestor as a real directory and the target's identity; a missing, edited or moved file falls through to official download. A changed template resolving to a different output directory must **never** use an old receipt, even if the old file exists; it may adopt only after a fresh transfer if within the new root. Preserve session-lock timing and atomic, private receipt writes (`src/campusctl/material_files.py:606-697`).
- JSON keeps the standard v1 envelope and existing `result.material` keys: `entity_id`, absolute `path`, `display_name`, `filename`, `size_bytes`, `sha256`, `outcome`, and `provenance.{provider,course_id,board_item_id,file_id}` (`src/campusctl/commands/materials.py:167-182`; `docs/contracts/materials.md:7-13`). Outcomes: `saved` = new file, `reused` = identical file in the output directory (including case/NFC variants or an existing digest alternate), `adopted` = identical file outside that directory but under the course root, `skipped-existing` = verified receipt (including an adopted path). Human output adds `Adopted: <absolute path>` beside existing labels (`src/campusctl/commands/materials.py:326-343`). No new CLI flags; update `docs/contracts/materials.md` and `docs/configuration.md` in implementation.

## Open questions

- There is no verified semester in material rows or roster. Is manual `materials.semester` acceptable indefinitely, or should a later, separately observed LMS/catalog change provide an automatic semester? Do **not** block this local feature on an unverified LMS field.
- On filesystems lacking reliable no-follow/identity checks (notably Windows reparse-point races), can adoption meet the no-symlink/no-unverified-bytes invariant? If not, fail adoption with `output-path-conflict` rather than relax verification; verify on supported Windows before claiming support.
