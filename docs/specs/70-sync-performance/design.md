# Sync performance — design and ownership contracts

[Spec](spec.md) · [Tasks](tasks.md). Preserve 50's `run_sync` return shape; no optimization-specific public result schema. These proposed APIs are new; source evidence below establishes why they are needed.

## Phase 1: opt-in observations

New `src/campusctl/profiling.py` exposes a no-op-by-default span recorder using `perf_counter_ns`. Use bounded in-memory aggregates, not synchronous per-request file logging. `--profile` is root-only and valid for sync/refresh; unsupported commands return usage-error. U5 owns registration. Emit one prefixed stderr line `campusctl-profile: <JSON>` at completion or failure; stdout remains the normal envelope. On failure close known spans and mark them failed, without serializing exception messages. Private profiling output is written only if the harness explicitly requests a destination.

The following shape uses illustrative counts/timings, not measured trial output:

```json
{"schema_version":1,"run":"<ephemeral-ordinal>","mode":"headless","scope":["assignments","notices","materials"],"outcome":"ok","wall_ns":235000000000,"spans":[{"phase":"extract","domain":"notices","course":1,"window":2,"count":1,"inclusive_ns":1000,"exclusive_ns":800}],"counts":{"course_selections":7,"documents":35,"requests":140},"dropped_events":0}
```

`course`/`window` are ephemeral ordinals, not hashed reusable IDs. Fixed phase names: lock, playwright, launch-connect, user-agent, auth, roster, todo, course-selection, document-commit, response-completion, guard-headers, guard-decision, guard-disposition, idle, dom-ready, extract, archive-page, modal, attachment-list, archive-restore, merge, serialize-write, teardown. Record overlapping/nested spans with parent identity internally; aggregate inclusive/exclusive times without summing overlapping wall durations. Fixed route categories and disposition counts only; no URLs, queries, headers, bodies, credentials, tokens, course names/IDs, filenames or raw errors. Buffer bounds and dropped count prevent unbounded allocation; final timing comparisons require zero dropped relevant spans.

Harness `tools/profile_sync.py` takes `--baseline-command-json '<argv-array>' --candidate-command-json '<argv-array>' --trials 5 --output <private-directory>`, executes argv without a shell, alternates A/B then B/A, and requires explicit `--allow-live` for non-fixture targets plus separate owner authorization. It must not itself bypass headless gates or discover credentials. Validate minimum trials=5; preserve nonzero exits, record reliability, and refuse an improvement score until five complete trials per arm exist. Capture CPU deltas/wall, event-loop lag, RSS and PSS where available for separate Python/driver/Chromium process groups; unsupported platform metrics are null, not zero. Independent browser tracing for script/layout/decode is a separate diagnostic run, not part of the median. Private normalized record comparison occurs locally; exported report contains equality/difference categories/counts, not real record content.

## Phase 2: one guarded session, serial sections

New `src/campusctl/providers/cnu/sync_all.py` owns browser/login/roster/guard lifecycle. `src/campusctl/sync.py` delegates multi-domain execution to it after this phase lands. Individual-domain wrappers call the same course collectors with their narrower selection; remove duplicate traversal implementations, not keep a hidden old path as fallback. Browser lock spans login through final publication/cleanup; never nest open_session calls (`browser.py:305-409`).

Freeze a `CourseSelection` immutable record in `course_context.py` with canonical course_id, ordinal, selection epoch, validated session response identity and committed course-entry document identity. It is created only from the normal UI's exactly-one successful `addSessionCourseInfo` response decoded before the next navigation; `body.data.course_id`, active topbar and selected roster ID must agree. Its lifetime ends at another selection, unexpected course navigation or fatal guard denial. It contains no encrypted body or token and is never persisted. This replaces notice's private selection lifecycle, not its proof (`notices.py:552-607`).

Collectors consume `(page, course, selection, section_guard)` and return complete rows or a domain/course failure; they never log in, select a different course, own browser lifetime, or publish catalogs. Lecture collector runs against the validated course-entry page before other sections, retaining existing LV/media/parser semantics. Assignment/notice/material collectors preserve their own committed document, first relevant request order, response completion, Referer, selected course, pending/duplicate and DOM completeness checks. Notice todo snapshot happens once under notices.sync before courses; todo failures mark affected notices stale but do not disable other domains. A failed section may continue only if the current course/session binding remains provable; otherwise remaining domains for that course fail and the next course must establish a new validated selection. No mid-run re-login/retry.

### Policy transition protocol

Keep one context-wide `route('**/*')` installed throughout post-login collection. Change policy/operation inside that handler only at a reviewed barrier; never unroute/reinstall between sections. No permanent union authority. `UiRequestInterceptor._handle` currently awaits headers before reading `_operation` (`ui_policy.py:719-733`); capture immutable policy/operation/epoch at callback entry **before its first await**, so a queued old request cannot borrow new authority.

At section completion: retain observers for late relevant responses; drain outstanding relevant tasks with existing bounded settling; verify current guard and section proof; quarantine the old epoch; activate only the next operation's explicitly reviewed navigation window. Validate request initiator document/frame/Referer against epoch and selected course, not just current operation. A late request from an old document remains subject to its old operation or is denied; it cannot be relabeled new by arrival time. If the browser cannot establish this provenance, fail closed and retain settling, rather than claiming safe switching. The first denial latches for the entire run, including transition callbacks; never reset it per section. No body is consumed or result published after denial. Selected-file authority is never enabled in metadata sync.

### Publication and stale semantics

Stage rows for each domain/course in memory; build merges with the existing domain merge routine and lecture health extension. A normal course failure affects that domain only; successful empty sections replace old rows. Preserve unknown enrollment, removal-deferred and filtered no-touch behavior (`domain_catalog.py:256-368`). Run-wide policy denial publishes **no staged catalog**. Complete response/transition observers and final guard check before any catalog write; close the browser context while the catch-all is still active, then publish under the still-held session lock. This requires separating lock ownership from browser cleanup without introducing a second lock or nested open_session; P2 owns that refactor and its contention/cleanup tests. CDP is not closed: detach/close only campusctl-owned pages after settling; if shared-page activity cannot be safely quiesced, keep that execution path gated rather than unguarding an active page for publication.

Catalogs remain individually private atomic files, not a claimed multi-file transaction. Prevalidate/serialize all domain catalogs before replacement; an I/O failure after one replacement produces an aggregate partial result that names committed domains and failed/not-started ones. No fabricated rollback. Security failures are checked before this publication stage and cannot be downgraded to per-course stale success.

## Phase 3: prove archive stays bound

Change only the restoration block at `materials.py:468-475` and its necessary state helpers. Capture course selection epoch, document identity, page index/size/total and ordered post IDs/titles before opening the modal. After close, require same exact state and no visible modal/backdrop, no unexplained pending/duplicate requests, and guard clean. `_archive_state` currently checks page/counts but is not by itself course/document proof (`materials.py:354-372`). If any nonfatal proof is unavailable, execute existing guarded archive menu reload plus pagination restore, then recheck all state. Identity mismatch after restore fails the course. Policy denial is fatal, never a restore retry. Retain per-modal bound attachment response, file-ID uniqueness and final counted-total checks. The fast path does not reuse old attachment metadata or skip posts.

## Independence and limits

A read-only performance review estimated 40–80s traversal and 15–40s modal savings; these are estimates and deliberately not used as measured outcomes. Counts-only equivalence risks shared-confirmation bias; independent fixtures and full-record control output fix that. The proposal is not an independent performance evaluation. The integration owner must preserve raw private trial metadata sufficient for another reviewer to reproduce medians and reject incomplete trials; public reports must remain sanitized.
