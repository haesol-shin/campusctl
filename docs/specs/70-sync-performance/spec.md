# v0.4.0 — measured sync performance

[Constitution](../constitution.md) · [Design](design.md) · [Tasks](tasks.md). Based on a read-only performance review and actual baseline source. Estimated savings are hypotheses, not measurements; overlapping estimates must not be summed. Owner-supplied baseline is 235 seconds headless on a low-power ARM host for seven courses across assignments/notices/materials. It is not an all-four-domain timing and must not be compared to full v0.4.0 sync without a matched control.

## Three phases, in order

1. **Instrumentation and profiling harness.** Opt-in global `--profile` emits sanitized phase metrics on stderr, never extra stdout JSON. Measure existing execution before optimizing. Capture nested monotonic spans and request/document/selection counts; collect Python, Playwright driver and Chromium components separately. Audit baseline conditions, including temporary headless rejection bypass, fresh/persistent profile and actual process coverage. The existing benchmark reportedly measured Chromium-tree CPU/RSS; aggregate CPU greater than wall time does not prove the critical path CPU-bound, and summed RSS double-counts shared pages.
2. **Combined serial course pass.** Full sync uses one session, one authentication, one roster extraction, one global notice auxiliary snapshot, then one validated course selection feeding lecture extraction and assignment/notice/archive sections serially. Lecture collection reuses the course-entry lecture page only when its extraction contract is satisfied; do not ignore lectures to make 'full sync' fast. One selected course cannot be shared across concurrent tabs because LMS selected course is server-session state. Retain individual-domain commands and single-domain results. Operation-specific policy switching has no unguarded window, uses fresh section binding checks, and retains a run-wide denial latch. Domain failures/stale merges remain independent.
3. **Conditional archive restoration elision.** After closing each attachment modal, keep the current archive page only if course identity, committed page/document, page number, totals, exact ordered posts and absence of modal/backdrop are independently proven unchanged. Otherwise use the existing guarded restore navigation and compare its full state. A close call succeeding or unchanged row count is not proof. Inspect all posts and all pages; no metadata caching by ID/title/date/count. No archive detail fallback.

## Measurable gates

Use five successful complete matched trials per condition, interleaved baseline/candidate, with separate cold and warm populations. Report median and min/max, wall/CPU/memory, success/failure counts and exact record equivalence. Failed/partial/stale runs remain in reliability reporting but never count as fast complete trials. Synthetic expected fixtures must be independently authored; do not let the candidate parser generate its own oracle. Owner-authorized live results compare full normalized record sets, not counts alone.

- Phase 1: five profiled/unprofiled matched trials; median wall overhead <=5%; each requested phase accounted for, no double-counted nested totals, zero private identifiers/secrets in output. Profiling/tracing runs are separate from final uninstrumented timing trials. If overhead exceeds 5%, reduce instrumentation cost before using it to judge later phases.
- Phase 2: on matched seven-course three-domain scope, course selection count drops from the baseline's expected 21 (verify by phase 1) to exactly 7, with one session/auth/roster snapshot and complete per-domain record/error equivalence. Target at least 15% median wall improvement versus newly measured matched baseline (235s gives an illustrative <=199.75s target, not a promise). Also measure all-four-domain full sync versus its own matched baseline; no >5% median regression and same one-selection-per-course invariant. Keep safety/completeness gates even if speed target is missed; owner review decides release, never weaken checks.
- Phase 3: for synthetic workloads with M>0 attachment-bearing posts and unchanged page state, archive restoration documents drop by M; when restoration cannot be proven, exact original restore behavior remains. Five-trial archive-phase median improves at least 10% versus phase 2 and end-to-end median does not regress >5%. Report M explicitly: material file row count is not post count. Final live five-trial comparison is a separate authorized gate.

## Explicitly rejected shortcuts

No parallel course tabs/shared mutable sessions; no new authenticated-session concurrency. No narrow routing plus after-the-fact listener as sole protection. No static extension/resource-type bypass of origin, redirect, Range, logging/media or selected-file checks. No blanket API/style/font/image blocking, especially no suppression of reviewed `getStdActivityStatus`. No smaller timeouts or removed duplicate/pending checks masquerading as successful speedups. No direct JSON requests or encrypted-body replay. No unchanged-title/ID/date/count attachment cache. No removal of DOM identity/actionability checks or detail-page navigation for missing metadata. No `--no-sandbox`, disabled web security/site isolation, single-process mode or indiscriminate GPU disablement. Reviewer ideas about explicit readiness, guard indexing, additional assets, incremental metadata, JSON parsing or launch tuning are **not v0.4.0 implementation phases**; require a separately measured/reviewed proposal.
