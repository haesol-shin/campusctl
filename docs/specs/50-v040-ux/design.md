# CLI and catalog UX design

[Requirements](spec.md) · [Constitution](../constitution.md)

`course_selection.py` resolves exact course IDs before human roster numbers or unique normalized label substrings; JSON requires exact IDs. `catalog_view.py` builds the sorted local roster from available catalogs, including domain-only first syncs, and stores private last-printed course/material selections. Each selection is bound to catalog generation and bytes; a rewrite yields `selection-stale`, missing snapshot `selection-missing`, invalid index `selection-invalid`. Resolve the selected ID before network work and recheck snapshot under the session lock; an invocation's own writes do not remap its selected scope.

`sync.py` validates the selected domains, browser modes and course scope, then runs the shared course traversal. One roster and global to-do are shared; one selected course supplies section-specific captures. Single-domain results preserve their native shape; multi-domain results place `status`, `result` and `errors` under `result.domains[domain]` in canonical order. A partial per-domain failure retains that catalog's prior course rows without preventing independent sections from committing. `--profile` records timings on stderr.

All lists expose cache age, advisory staleness and failed-course coverage; `--refresh` invokes the same single-domain sync path and does not mask failure with cached rows. `status.py` reads each catalog once, uses Asia/Seoul for dates and returns complete JSON arrays with compact terminal summaries. Guided setup derives progress from actual config, browser and credential state on each run, never from a progress marker; no password appears in arguments or files. Global browser flags override validated config and precede the subcommand; a headless CDP/playback request fails before browser work.
