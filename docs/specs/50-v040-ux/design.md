# v0.4.0 UX — design and frozen interfaces

[Spec](spec.md) · [Tasks](tasks.md). Paths below are relative to the repository; existing-code references are baseline `adb2684`. New module/API names are implementation decisions, not claims about existing code.

## Shared interfaces and ownership

The UX integration lane owns `cli.py`, `presentation.py`, all three `commands/{assignments,notices,materials}.py`, public contracts and release-facing docs. Other lanes expose functions; they do not compete for parser/renderer edits. The performance lane later owns provider orchestration, not command registration. Detail-fetch command edits land after UX integration; see 40-fetch's delta.

- New `course_selection.py`: `resolve_course(selector, courses, *, ids_only, printed_roster=None) -> str | None`. `None` means unfiltered. Exact ID comparison is literal and takes precedence even for numeric IDs. After exact lookup fails, `ids_only` (resolved JSON output) immediately returns `course-index-unavailable` for numeric input or `course-id-required` otherwise, both user-action/2 with `Use a full course ID from 'campusctl courses list --json'.`; never enter index/name normalization or matching. The latter includes an unknown opaque ID because IDs have no guessed syntax. Sync supplies its live roster for this lookup when needed, so valid full IDs require no cache. Human names remove every `str.isspace()` character and casefold; require at least one normalized character. Human indices require the generation-checked printed roster below. Return only canonical course ID. Human ambiguity errors carry candidates in `result.candidates:[{course_id,label}]`, using the existing safe error shape separately.
- New `catalog_view.py`: `course_roster(root)`, `cache_metadata(catalog, *, now)`, selection snapshot helpers and local catalog-generation identity. Course roster is the deduplicated union of readable local catalogs, preferring lecture label, then assignments, notices, materials; sort by full course ID, never locale-dependent label sorting. Human `courses list` displays that order and an `index`; JSON returns full IDs without numeric selection aliases. This replaces lecture-only offline course discovery (`cli.py:476-481`), allowing a domain-only first sync. Missing catalogs are skipped, corrupt/unsupported present catalogs are errors, and no available catalogs yields `catalog-missing` with `campusctl sync` remediation. No browser/config read. Human indices resolve only against the last successfully printed human roster snapshot; recomputing current positions is forbidden.
- Sync full IDs require no pre-existing cache: validate exact membership against live discovery. JSON input is never normalized or substring-matched; a fresh-cache name fragment therefore fails the same IDs-only lookup, even if it uniquely matches a live course name. Human name selectors may use the live roster when no local roster exists; with local roster, resolve once before refresh and revalidate the chosen ID live. Human numeric selection always requires a printed roster snapshot. Resolve once for all selected domains, then carry the ID and snapshot precondition into the locked network operation.
- New `sync.py`: `run_sync(config, root, domains, course_id, *, headless, profile=None)` returns result/errors. UX initially dispatches existing domain syncs serially; phase 70 replaces internals, preserving this contract. Single-domain result remains native. A domain operational failure may leave other successful domains available, but authentication failure, busy or policy denial stops the invocation; no automatic retries. Before combined phase 70, already committed domains are explicitly reported, never rolled back or hidden. In phase 70 all collection is staged until the run-wide guard passes.

Multi-domain `result` is exactly shaped as follows (domain keys present only for the requested set; `not-started` has empty result and errors):

```json
{"domains":{"lectures":{"status":"ok","result":{"courses":1,"lectures":0,"incomplete":0,"failed_courses":[],"catalog":{"generated_at":"<UTC timestamp>"}},"errors":[]},"notices":{"status":"not-started","result":{},"errors":[]}}}
```

Each completed domain status uses existing envelope statuses. Outer errors flatten domain errors in canonical domain order. All ok gives ok/0; any work committed plus failure/not-started gives partial/1; before any work, propagate original user-action/2, busy/75 or error/1. A policy failure is never ok; 70's staged run reports error/1 when nothing committed. Human output names each requested domain and its outcome.

## Browser option resolution

New `browser_options.py` resolves a nullable root parser override against validated Boolean `browser.headless`, default false. `config.py:61-64` currently validates browser strings only; reject non-Boolean headless values with config-invalid/2. Global options precede command; retain `--json`-anywhere behavior (`docs/contracts/cli.md:27`) unchanged. Both browser flags together are usage-error/2. Network entrypoints receive an explicit effective Boolean, including lecture sync/play, refresh and setup's optional sync; remove hardcoded false only where the 60 gate is cleared. Doctor uses effective mode: Linux no-display is not an error for supported headless local operations; Windows display_available remains null (`cli.py:203-212`). CDP mode cannot be changed by these flags; effective headless still returns headless-unavailable. No inferred server default and no configuration file rewrite for a one-shot override.

## Freshness, failures and refresh

All list `result.cache` keeps existing fields and adds `age_seconds`, `stale`, `stale_after_seconds:21600`, `refresh_command`. Age is floor(max(0, UTC now minus generated_at)); malformed time is catalog-invalid, missing legacy timestamp remains unknown only where the existing reader accepts it. A future timestamp produces age 0 plus `clock_skew:true`, never a negative age; `clock_skew` otherwise false. `stale` is true for age >21600, unknown enrollment, failed courses or unknown timestamp. Human lists distinguish 'generated N ago' from failed-course retention. `courses list` reports `cache.sources` keyed by contributing domain and uses the oldest contributing timestamp for its aggregate age, avoiding a newly synced domain hiding an old roster.

Extend lecture catalogs with optional `failed_courses:[{course_id,label,reason}]` and `enrollment_state` using the domain convention. Legacy lecture catalogs remain readable, but absence of failure metadata yields `enrollment_state:"unknown"`, not proof of freshness. Full discovery failure preserves lecture records/timestamp and marks enrollment unknown; filtered discovery failure leaves it untouched. Preserve existing lecture scoped merge and successful-empty rules (`providers/cnu/sync.py:97-110,132-151`; `docs/contracts/cli.md:225`). Domain merges remain `domain_catalog.py:256-368`: retained failed rows never become fresh merely because the file has a new timestamp. This release reports catalog generation age, not a newly invented per-row freshness guarantee.

`list --refresh` calls the same single-domain run_sync entrypoint, then reads a fresh snapshot and returns ordinary list fields plus `refresh:{status,result,errors}`. Successful refresh returns ok; partial refresh returns available rows with partial/1 and retained-course warnings; fatal refresh may expose readable prior rows only with the failure status and `refresh` object, never ok. If there is no readable catalog, return the refresh failure with no rows. Resolve course once; preserve `lectures list --all`. No list selection snapshot on a failed/partial material refresh. No automatic refresh on age alone.

## Persisted course indices

After fully rendering and flushing a successful human `courses list`, atomically persist `<data-dir>/selection/courses-last-list.json` privately. JSON output and failed/partial refresh do not replace it. Use the same flush/write/error and last-successful-writer semantics as materials snapshots. Shape:

```json
{"schema_version":1,"roster_generation":"<sha256-of-canonical-roster-and-source-generations>","sources":{"lectures":{"generation_id":"<opaque-write-id>","sha256":"<catalog-byte-digest>","generated_at":"<UTC timestamp>"},"assignments":null,"notices":null,"materials":null},"courses":[{"course_id":"<course-id>","label":"<course-label>","class_no":null}],"printed_at":"<UTC timestamp>"}
```

Hash canonical ordered roster records plus the four source-generation entries, including missing sources as null. Bind to every contributing catalog's write generation and digest; a changed/added/removed source or changed order/ID/label invalidates the snapshot, even if its generation timestamp matches. Extend generation IDs to lecture catalog writes as well as domain writes; legacy files use null generation_id plus exact byte digest. A metadata-only source rewrite may conservatively invalidate indices; never silently remap them. Before resolving a number, compare the current roster generation with the persisted one, then select `courses[number-1].course_id`. Missing snapshot returns `selection-missing`; malformed/out-of-range index returns `selection-invalid`; changed generation returns `selection-stale`, all user-action/2 with `Run 'campusctl courses list' again.` No index fallback to the live roster or a name is allowed.

Local list/status validate the generation against the same immutable source snapshots used for their output. Network sync/refresh recheck it under the existing exclusive session lock before browser startup, then freeze the resolved ID for the invocation; the invocation's own subsequent writes do not remap or invalidate its already accepted scope. A concurrent earlier catalog rewrite must fail before navigation. Full IDs and human name selections do not depend on the printed roster snapshot.

## Persisted materials numbers

Keep catalog row order as returned by the current list handler; numbers are 1..N over the exact filtered rendered sequence, not per-course counters. Snapshot path: `<data-dir>/selection/materials-last-list.json`, private atomic write using existing storage patterns. Shape:

```json
{"schema_version":1,"catalog_generation":{"generated_at":"<UTC timestamp>","sha256":"<catalog-byte-digest>","generation_id":"<opaque-write-id>"},"course_id":null,"entity_ids":["<material-entity-id>"],"printed_at":"<UTC timestamp>"}
```

Add optional `generation_id` to domain catalogs at every atomic write (including metadata-only enrollment writes); generate a fresh opaque UUID on every replacement. Preserve old schema-1 catalogs: their generation_id is null and byte digest binds that snapshot until the next write. Digest protects against same-generation external modification; generated_at alone is insufficient (`domain_catalog.py:314-319,362-368`). The snapshot is auxiliary local state, never an LMS catalog or authority source.

Ordinary human list: load one catalog snapshot, construct and render the full numbered output, successfully flush, then atomically persist the snapshot. JSON does not create/replace it and adds no numeric entity aliases. A broken pipe or persistence failure does not install a new snapshot; fail safely with `selection-write-failed`/error/1. Concurrent human lists are last-successful-snapshot-writer wins; state this single-account CLI rule, not terminal-specific history. A download number reads snapshot and catalog, compares generation and digest, resolves one ID, then rechecks the generation inside the existing session lock before any browser startup/receipt success. If changed, return `selection-stale`/user-action/2 with 'Run campusctl materials list again'; never remap the same number. Missing snapshot uses `selection-missing`; invalid/out-of-range uses `selection-invalid`. Exact full ID download does not depend on this snapshot. Picker uses the same catalog/generation binding, only downloadable rows as choices, keeps their printed numbers, and supports explicit cancel; it never turns Enter into 'first file'. Existing ID membership, media checks, live binding, typed bytes and receipts remain untouched (`commands/materials.py:185-203,272-305`).

## Status data and presentation

New `status.py`: `build_status(root, course_id, *, now)`. One immutable read per catalog; no shared global generation is assumed. Missing/invalid catalogs become per-domain coverage/errors; if any readable required source exists, status is partial/1 when another required source is missing/invalid. No readable required sources returns catalog-missing/user-action/2. Materials is required only for the stale-course coverage section, but missing materials still means incomplete coverage. Old or failed sources remain visible with warnings, not operational failure solely due to age.

```json
{"as_of":"<UTC timestamp>","timezone":"Asia/Seoul","window":{"start":"<RFC3339 timestamp>","end":"<RFC3339 timestamp>","end_inclusive":false},"assignments":{"due_soon":[],"unknown_due_count":0},"notices":{"unread":[],"unknown_count":0},"lectures":{"open_incomplete":[],"unknown_open_count":0},"coverage":{"lectures":{"state":"available","cache":{}},"assignments":{"state":"missing","cache":null},"notices":{"state":"available","cache":{}},"materials":{"state":"invalid","cache":null}},"stale_courses":[{"course_id":"<course-id>","label":"<course-label>","domains":["notices"],"reasons":["course-sync-failed"]}]}
```

Array entries preserve native catalog row fields; lecture entries add `next_at` (RFC3339 or null) and `next_kind` (`deadline`, `availability`, or null). Assignments: `is_submitted:false` only; parse displayed ISO date or date-time, date-only deadlines end at 23:59:59 Asia/Seoul; malformed/null goes to unknown_due_count rather than a guessed date. Notices: true in unread, null in unknown_count, false excluded. Lectures: completion incomplete and open true; count open null separately; nearest future due_date/available_from wins, deadline on ties. Date-only availability is local midnight; past deadlines are not future dates. Sort assignments and lectures by relevant timestamp, null last, then full entity ID. Sort unread by posted/date text where parseable newest first, then ID. Stale courses include selected courses in old catalog sources, failed-course records, or unknown-enrollment sources; merge domain/reason sets deterministically. Do not substitute todo rows or infer read/submission status.

Human status is a compact summary, not four complete lists: counts plus at most three entries for each actionable section and three stale courses, `+N more` and appropriate list commands; at an 80x24 terminal fit within 24 lines by showing IDs only via the suggested full list command. Narrow terminals may wrap; never truncate selectable IDs when shown. JSON arrays are complete, not limited to screen size. Test clock/date boundaries independent of machine timezone.

## Setup state machine

Refactor existing config/browser/credential functions for reuse rather than calling CLI subprocesses. Guided config stage must suppress config init's nested password/browser offers so the sequence is exactly config → browser → credentials → check → optional sync. Browser-only setup retains `result.browser` and `next`. Guided result adds `steps:[{name,status}]` (names config/browser/credentials/check/sync; statuses completed/reused/skipped/declined/failed) and `next` commands. Interrupted runs rely on durable config/install/keyring/catalog state; no password-bearing checkpoint. Install/password decline stops with user-action/2 `setup-incomplete`; optional sync decline is successful setup with sync skipped. Existing invalid config is never overwritten. Existing safe credentials are reused; helper config never invokes auth set. Ctrl-C keeps prior completed stages and uses existing interrupt behavior. Full sync failure returns its existing errors and preserves setup steps. Agent skill retains user-run password instruction and browser-download consent.
