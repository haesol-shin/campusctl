# Student-first CLI

[Constitution](../constitution.md) · [Design](design.md) · [Tasks](tasks.md)

`campusctl sync` selects all four metadata domains in canonical order (lectures, assignments, notices, materials). `--only` accepts a comma-separated subset. The combined pass authenticates once, reads roster/to-do once, selects each course once, and opens requested sections from its menu. Each domain/course succeeds or fails independently; failed catalogs keep previous rows with stale warnings. `--profile` before sync writes phase timings to stderr without a speed claim.

Human `courses list` prints course numbers and complete IDs. `--course` accepts an exact ID, a last-printed roster number, or a unique case/whitespace-insensitive name substring. Numbers fail if the roster/catalog generation changed. JSON calls require full course IDs. `materials list` prints one number per file, and `materials download NUMBER` selects one file from the last printed human list only while its catalog remains unchanged; an interactive bare download offers a single-choice picker. JSON download requires a full ID. Lists stay offline unless `--refresh` explicitly refreshes their domain. Older cache ages prompt an advisory, never an automatic network action.

`status` locally summarizes unsubmitted assignments due within seven days, known unread notices plus unknown-read count, and open incomplete lectures, with missing/stale/failed coverage. Lecture health is reported without calling the LMS. Asia/Seoul interprets timezone-less LMS dates. Guided dual-TTY `setup` sequences configuration, browser, hidden credentials/check and optional first full sync; JSON/noninteractive setup stays browser-only. Global `--headless`/`--headed` precede the command, override `browser.headless`, and default to headed. Local headless supports sync/material download, not CDP or official-player playback. Selected-detail fetch remains unregistered pending its [own gate](../40-fetch/spec.md).
