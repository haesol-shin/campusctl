## Integration order and constraints

U1 freezes local APIs → U2/U3/U4 in parallel → H1 browser-options/config lane and H2 provider mode handoff → U5 shared parser/renderer/commands → 70 provider handoff → 40 domain command integration → U7. H1 owns config/browser mode files, not U5's CLI. U3's optional sync calls the frozen `run_sync` interface; inject a callable until U5 provides it, never ship a stub. No two implementation branches edit a shared file concurrently.

Before handoff, scoped behavioral proof must show: `materials list --course <course-id>` prints N rows; `materials download 1` resolves the exact first printed ID; a catalog rewrite returns selection-stale without transfer; `--json` bare download never prompts. Status must show unread and unknown separately even when todo omits board notices. Full-ID downloads remain one selected file and retain receipt verification.

U1/U5 course-selection acceptance (required): persist a flushed human roster, then add/remove a lower-sorting course, rename a label or rewrite a source in the same timestamp second; numeric `--course` must return selection-stale rather than select a new row. Cover missing snapshot, JSON list not replacing it, failed snapshot publication, and a rewrite between preliminary resolution and locked network entry. Full numeric IDs still win and full-ID selection remains independent. Across sync, every filtered list/refresh and status, JSON rejects both non-ID indices and unique name substrings, including a fresh-cache live roster; no substring fallback may occur. Human normalized names remain supported. Tests belong to `tests/test_course_selection.py`, `tests/test_catalog_view.py`, `tests/test_selection_cli.py` and `tests/test_sync_dispatch.py`; run with `uv run pytest -q <owned-test-paths>` after those lane edits.
