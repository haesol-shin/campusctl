# Materials commands

Bare `sync` collects lectures, assignments, notices and materials in one combined pass, selecting each course once. `sync --only materials` narrows it to archive metadata without downloading bodies. `materials list [--course COURSE_ID] [--refresh]` reads the local catalog unless `--refresh` first syncs materials. `materials download [ENTITY_ID|NUMBER] [--out DIRECTORY]` saves one revalidated official non-video attachment: human numbers refer to the last printed materials list and fail after a catalog change, while an interactive bare invocation offers a single-file picker. JSON requires one full ID. Global `--headless` and `--headed` control local Chromium; CDP headless returns `headless-unavailable`.

LMS page requests run without an interceptor. After one verified course selection, the archive opens through its rendered menu; its completed list response must belong to the committed archive page. The archive shell and total count must agree with the post rows before an empty or nonempty result is published. Post attachment-list responses must finish before their controls are read; a missing or unresolved post fails the course rather than borrowing another post's controls. A failing materials section retains that course's previous rows and does not prevent other domains from completing. Errors name the domain and failing step.

The materials capability advertises `list` and `download`; sync is also available through `sync --only materials`. Human lists number each file and display its complete ID, course, archive title, filename, downloadability and stale warning. A post whose modal and inline controls cannot be resolved fails its course. Human downloads show `Saved:`, `Reused:`, or `Skipped existing:` and a complete absolute path. JSON uses the standard versioned envelope.

A listed ID is selectable when its row is `downloadable:true`, including a retained stale row; the command then revalidates its parent and file in the LMS. Unknown/moved IDs return `entity-unknown` (exit 2), and a listed non-downloadable row returns `unsupported-media-type` (exit 2). A receipt permits `skipped-existing` only for the same full ID and absolute output directory when its target is a regular non-symlink file inside that directory whose bytes match the receipt's size and SHA-256. This check runs inside the session lock before authentication or navigation. Otherwise the command authenticates, rechecks the selected board/file identities, binds one official file URL, verifies response type/signature and at most 200000000 bytes without HTTP Range, then publishes the file and receipt atomically.

`--out` must be a real directory, not a symlink; absent directories are created privately. Files default to `<Downloads>/campusctl/<safe course label>/`: Windows uses the OS Downloads known folder, including redirection; Linux uses the configured XDG Downloads folder when available; macOS uses `~/Downloads`. Receipts remain private. The official control or `getAttachFileList` display text supplies the basename, never the storage URL; remove a trailing `바로보기`, then normalize and limit it to 200 UTF-8 bytes. On Windows a long basename is shortened to fit the 250-UTF-16-unit absolute-path limit, or `output-path-too-long` suggests a shorter `--out`. ZIP is stored, not extracted. Allowed extensions and strict PDF/PPTX/ZIP MIME/signature pairs are specified in the [constitution](../specs/constitution.md#owner-decisions); other types require matching known signature or text validation, never MIME alone. Video/audio and external files remain metadata-only.

JSON uses the [standard v1 envelope](cli.md#response-envelope-and-exit-codes); its `status` is `ok`, `partial`, `user-action`, `error`, or `busy`. Catalog/selection/media/size/output/headless errors are user-action (exit 2); rejected selected-file transfers and other operational errors exit 1, partial sync exits 1, and `session-busy` exits 75. Missing catalog remediation: `campusctl sync --only materials`. No signed file URL, credential, or unredacted Playwright error is persisted.
