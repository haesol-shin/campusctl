# Materials commands

Bare `sync` collects lectures, assignments, notices and materials in one combined pass, selecting each course once. `sync --only materials` narrows it to archive metadata without downloading bodies. `materials list [--course COURSE_ID] [--refresh]` reads the local catalog unless `--refresh` first syncs materials. `materials download [ENTITY_ID|NUMBER] [--out DIRECTORY]` saves one revalidated official non-video attachment: human numbers refer to the last printed materials list and fail after a catalog change, while an interactive bare invocation offers a single-file picker. JSON requires one full ID. Global `--headless` and `--headed` control local Chromium; CDP headless returns `headless-unavailable`.

LMS page requests run without an interceptor. After one verified course selection, the archive opens through its rendered menu; its completed list response must belong to the committed archive page. After each list response, page change or restoration, sync waits for the archive shell, total count and full expected post rows to agree before publishing an empty or nonempty result. Post attachment-list responses must finish before their controls are read; a missing or unresolved post fails the course rather than borrowing another post's controls. A failing materials section retains that course's previous rows and does not prevent other domains from completing. Errors name the domain and failing step.

The materials capability advertises `list` and `download`; sync is also available through `sync --only materials`. Human lists number each file and display its complete ID, course, archive title, filename, downloadability and stale warning. A post whose modal and inline controls cannot be resolved fails its course. Human downloads show `Saved:`, `Reused:`, `Adopted:`, or `Skipped existing:` and a complete absolute path. JSON uses the standard versioned envelope.

A listed ID is selectable when its row is `downloadable:true`, including a retained stale row; the command then revalidates its parent and file in the LMS. Unknown/moved IDs return `entity-unknown` (exit 2), and a listed non-downloadable row returns `unsupported-media-type` (exit 2). A verified receipt permits `skipped-existing` only for the same full ID and absolute output directory, and for adopted files only if adoption remains enabled with the same course root; targets must remain regular non-symlink files with matching size and SHA-256. Receipts use private schema 2 with `course_root` null for saved/reused files and the absolute root for adopted files; schema 1 receipts remain readable and migrate on update. This check runs inside the session lock before authentication. Otherwise the command authenticates, rechecks the selected board/file identities, fetches and verifies one official attachment, and publishes or adopts only after comparing actual bytes. `result.material` includes `entity_id`, absolute `path`, `display_name`, `filename`, `size_bytes`, `sha256`, `outcome` (`saved`, `reused`, `adopted`, `skipped-existing`) and `provenance` (`provider`, `course_id`, `board_item_id`, `file_id`).

The official transfer binds one selected file URL, checks response type/signature and at most 200000000 bytes without HTTP Range before any adoption or publication. The official control or `getAttachFileList` display text supplies the basename, never the storage URL; remove a trailing `바로보기`, then normalize and limit it to 200 UTF-8 bytes. Allowed extensions and strict PDF/PPTX/ZIP MIME/signature pairs are specified in the [constitution](../specs/constitution.md#owner-decisions); other types require matching known signature or text validation, never MIME alone. Video/audio and external files remain metadata-only.

`--out` is an ordinary directory argument and overrides the configured template for that call, disabling recursive adoption. Without it, `[materials].download_dir` may specify an absolute per-course template (see [configuration](../configuration.md)); otherwise files default to `<Downloads>/campusctl/<safe course label>/`, using the redirected Windows known folder, Linux XDG Downloads or macOS `~/Downloads`. Directory ancestors must not be symlinks. Optional `adopt_existing` scans at most four directory levels under the course component, up to 10,000 entries and 1,000,000,000 candidate bytes read. Candidates sharing the normalized primary filename are checked in priority order (exact destination, others in destination, then elsewhere under the course root): size, up to 64 KiB at both ends, then full byte comparison if larger than 128 KiB. Samples alone never authorize adoption. Same-directory matches are `reused`; matches outside are `adopted`; no match uses the existing no-clobber publication. ZIP is stored, not extracted. Windows publication observes the 250-UTF-16-unit absolute-path budget; `output-path-too-long` suggests a shorter `--out`.

JSON uses the [standard v1 envelope](cli.md#response-envelope-and-exit-codes); its `status` is `ok`, `partial`, `user-action`, `error`, or `busy`. Catalog/selection/media/size/output/headless errors are user-action (exit 2); rejected selected-file transfers and other operational errors exit 1, partial sync exits 1, and `session-busy` exits 75. Missing catalog remediation: `campusctl sync --only materials`. No signed file URL, credential, or unredacted Playwright error is persisted.
