# Materials commands

`campusctl sync --only materials [--course COURSE_ID] [--json]` refreshes official course-archive metadata without downloading file bodies. `campusctl materials list [--course COURSE_ID] [--json]` reads the local catalog without opening a browser. `campusctl materials download ENTITY_ID [--out DIRECTORY] [--json]` accepts exactly one full ID copied from the list and saves only its revalidated official non-video attachment. Network commands use a visible browser; `--headless` returns `headless-unavailable` until separately reviewed.

The `materials.sync` and `materials.download` guards permit exact LMS POST `/api/v1/week/getStdActivityStatus` XHR from `/std/lecture` only as a reviewed read-only route; aborting it displays a blocking server-communication modal. It is not counted as a suppression. Other unsuppressed logging-token paths remain denied.

The attachment-list `e` query is an opaque encrypted token; the guard accepts its reviewed base64 alphabet, including URL-encoded characters from that alphabet, without interpreting it as a plaintext course ID. The archive list response is bound to the first request after the archive page commits, not to the earlier course-row click.

The reviewed capability advertises `list` and `download`; sync is available via `sync --only materials`. The list displays the full selectable ID, course, archive title, filename, downloadability, and a warning for stale/unknown enrollment or failed courses. A failed course retains its previous rows. If a post's modal and inline controls cannot be resolved, the whole course fails; unreviewed post-detail `/std/archiveView` is not used. Human download output prints `Saved:`, `Reused:`, or `Skipped existing:` followed by a complete absolute path on one line, even on a narrow terminal. JSON mode produces one standard schema-version-1 campusctl envelope; `result.material` includes `entity_id`, absolute `path`, raw `display_name`, label-free `filename`, `size_bytes`, `sha256`, `outcome` (`saved`, `reused`, `skipped-existing`), and `provenance` (`provider`, `course_id`, `board_item_id`, `file_id`).

A listed ID is selectable when its row is `downloadable:true`, including a retained stale row; the command then revalidates its parent and file in the LMS. Unknown/moved IDs return `entity-unknown` (exit 2), and a listed non-downloadable row returns `unsupported-media-type` (exit 2). A receipt permits `skipped-existing` only for the same full ID and absolute output directory when its target is a regular non-symlink file inside that directory whose bytes match the receipt's size and SHA-256. This check runs inside the session lock **before authentication or navigation**. Otherwise the command authenticates, guards the archive, rechecks the selected board/file identities, transfers at most 200000000 bytes without HTTP Range, verifies response and content, publishes without clobbering, and writes a receipt. A fresh validated transfer matching existing output bytes is `reused`; changed bytes use one full-SHA-256-suffixed collision name, never overwrite the original.

`--out` must be a real directory, not a symlink; absent directories are created privately. By default files go under `<Downloads>/campusctl/<safe course label>/`: Windows uses the OS Downloads known folder (honoring redirection), Linux reads `XDG_DOWNLOAD_DIR` in `$XDG_CONFIG_HOME/user-dirs.dirs` when `XDG_CONFIG_HOME` is absolute (otherwise `~/.config/user-dirs.dirs`), and macOS uses `~/Downloads`; missing Windows/Linux settings fall back to the home Downloads folder. Receipts remain private under the campusctl data directory. The saved basename derives from the label-free `filename`, never the storage URL; it is normalized, traversal/device-name safe, and limited to 200 UTF-8 bytes. Windows shortens the basename further when needed to keep the absolute path at most 250 UTF-16 units, reserving space for private publication temporaries; a directory too long for those temporaries returns `output-path-too-long` with guidance to choose a shorter `--out`. ZIP is stored only, never extracted. The approved extension allowlist, signatures, strict observed PDF/PPTX/ZIP MIME pairs, and unobserved MIME handling are defined in the [materials design](../specs/30-materials/design.md#attachment-classification-and-response-guard-fr-005-fr-010fr-011-fr-020). Video/audio and external files remain metadata-only.

JSON uses the [standard v1 envelope](cli.md#response-envelope-and-exit-codes); its `status` is `ok`, `partial`, `user-action`, `error`, or `busy`. Catalog/selection/media/size/output/headless errors are user-action (exit 2); rejected policy requests and other operational errors exit 1, partial sync exits 1, and `session-busy` exits 75. Missing catalog remediation: `campusctl sync --only materials`. No signed file URL, credential, or unredacted Playwright error is persisted.
